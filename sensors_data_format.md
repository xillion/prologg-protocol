# Формат данных датчиков (Давление / Температура / Батарея)

Документ описывает, **что именно и в каком виде** устройство PT_LOGGER отправляет
по трём запросам: `get_temperature`, `get_pressure`, `get_battery_voltage`.
Предназначен для реализации приёмной стороны (Flutter).

---

## 1. Транспорт (краткий пересказ)

Полная схема кадра USB/COBS-сессии — в `usb_stack_description.md`
конкретной прошивки (не входит в этот общий submodule). Коротко:

```
[payload protobuf Response] [CRC-32/ANSI (4 байта, big-endian)] → COBS → 0x00
```

- **CRC-32/ANSI**: poly `0x04C11DB7`, init `0x00000000`, MSB-first
  (без bit-reflect), без final XOR. Полином «как в таблицах»,
  НЕ `binascii.crc32` (это IEEE, он не подходит!). CRC считается по
  protobuf-байтам **до** CRC и добавляется big-endian (старший байт первым).
- **COBS**: классический, закодированные байты, затем терминатор `0x00`.

Эталонная реализация для Python: `crc32_ansi`/`cobs_encode` в
`tests/test_protocol.py` каждой прошивки (генерируются одинаково,
см. `README.md` этого репозитория).

## 2. Envelope Response (общие поля)

```protobuf
message Response {
    ErrorCode error   = 1;   // varint, 0 = SUCCESS
    uint32   command  = 2;   // varint, эхо which_command из запроса
    oneof result {
        sint32 adc_temperature     = 5; // знаковый (zigzag-varint), с protocol_version 2
        uint32 adc_pressure        = 6;
        uint32 adc_battery_voltage = 8;
        ...
    }
}
```

- `command` всегда повторяет номер команды запроса:
  `get_temperature` = 3, `get_pressure` = 4, `get_battery_voltage` = 7
  (см. `Request` в `prologg.proto`).
- При успехе `error = 0` (поле 1 не кодируется — nanopb опускает нулевые
  varint). При ошибке вернётся код из enum `ErrorCode`:
  - `TEMP_GET_FAILED = 21` — ошибка MAX31888 (нет устройства на шине,
    CRC-ошибка шины, FIFO пуст);
  - `ADC_GET_FAILED = 22` (зарезервирован).
- В oneof присутствует **ровно одно** поле результата — по нему клиент
  определяет тип ответа (см. теги `5/6/8`).

## 3. Температура — `Response.adc_temperature` (поле 5, sint32)

**Что кладёт прошивка:** знаковое 16-битное слово датчика MAX31888,
напрямую в sint32-поле (zigzag-varint на проводе, знак кодируется явно
— начиная с `protocol_version = 2`; до этого поле было `uint32` с
неявным контрактом «приёмник обязан привести к int16»).

```cpp
int16_t raw = static_cast<int16_t>(temp / 0.005f);
resp.result.adc_temperature = raw;   // implicit int16_t -> int32_t, знак сохраняется
```

**Формула приёма:** значение приходит уже знаковым — просто
`T°C = adc_temperature * 0.005`, без ручного приведения к int16 (это
теперь делает сама схема, а не приёмник).

**Пример из лога:** raw = 5872 → 29.36 °C; raw = 5864 → 29.32 °C.

**Границы:** рабочий диапазон MAX31888 −20…+105 °C → raw ≈ −4000…+21000.

**Пояснения:**
- Разрядность данных = 16 бит (0.005 °C/LSB), именно её сообщает
  `DeviceInfo.adc_bit = 16` (поле 7). В текущей прошивке всегда 16.
- Семантика по даташиту MAX31888 п.12: `T = значение × 0.005`, left-justified,
  двухомплементное.
- Измерение: `measureBlocking()` = триггер конверсии по 1-Wire → ожидание
  ~20 мс → чтение FIFO с проверкой CRC16.

## 4. Давление — `Response.adc_pressure` (поле 6, uint32)

**Что кладёт прошивка:** сырой 16-битный код АЦП канала PA_3 (0…65535),
усреднённый:

```cpp
uint16_t get_adc() {
    analog_pwr = 1;
    DAC: vfb -> устройство компенсации, vref -> опорная коррекция датчика
    settle 10 мс;
    256 выборок, первые 16 отбрасываются, среднее по 240;
    return avg;   // 0..65535
}
```

**Формула приёма (напряжение на входе АЦП):**

```
V_adc [В] = raw / 65535 × 3.3
// пример: raw = 64629 → 3.25418 В (лог: 3254.18 мВ)
```

**ВАЖНО: прошивка НЕ пересчитывает давление в физические единицы.**
Полное напряжение сигнала на АЦП зависит от аналогового тракта:

- усилитель (коэффициент задаётся цифровым потенциометром AD5142A,
  `R2 = 100000/(gain − 1)` Ом);
- компенсация неидеальности датчика через DAC `vref` (у вас 0.1 В);
- смещение `vfb`;
- характеристика конкретного датчика давления.

Параметры для пересчёта клиент берёт из ответа `get_analog_params`
(поле 10, сообщение `AnalogParams { float gain, vref, vfb }`) и из
`get_calibration_info` (поле 13), если он заполнен.

**Контроль достоверности («rail»):**
- `raw == 0` или `raw == 0xFFFF` (и близкие значения ~65535) — выход
  усилителя в насыщении/обрыв линии: прошивка логирует
  `WARNING: ADC rail detected`, но **возвращает SUCCESS** — проверять
  на клиенте.
- В норме разброс одиночных выборок мал; при плохом контакте/наводке
  появляются «провалы» — прошивка усредняет 240 выборок, этого обычно достаточно.

## 5. Батарея — `Response.adc_battery_voltage` (поле 8, uint32)

**Что кладёт прошивка:** сырой 16-битный код АЦП канала PA_1,
усреднённый по 256 выборкам (без отбрасывания).

**Формула приёма:**

```
V_adc [В] = raw / 65535 × 3.3          // напряжение на выводе АЦП
V_bat [В] = V_adc × 1.511              // делитель на плате (константа железа!)
// пример: raw = 55642 → 2.80184 В × 1.511 = 4.234 В (лог: 4234 мВ)
```

Пояснения:
- Делитель **1.511** — аппаратная константа платы; прошивка её НЕ передаёт
  в ответе (только логирует в отладочный порт). Клиент должен знать её
  или получать из своей конфигурации.
- Опорное АЦП = 3.3 В (оба канала — давление и батарея).
- Типичный диапазон: 3.0…4.3 В (Li-ion) → raw ≈ 39400…56500.

## 6. Примеры из реального лога (отладочный порт ttyUSB0)

Каждый запрос-ответ можно сверить с отладочными строками:

```
handle_get_temperature
  FIFO fill before: 12
  OK: temp=29.36 C raw(16bit)=5872        ← adc_temperature = 5872
  FIFO fill after: 13

handle_get_pressure
  DAC: vfb=1.0000 ref=1.0000 (V)          ← действующие AnalogParams
  ADC press: avg=64629 min=64159 max=65055 spread=896
  ADC press: 3254.38 mV (ref 3.3V, 64629/65535)
  Pressure raw=64629, 3254.38 mV           ← adc_pressure = 64629

handle_get_battery_voltage
  ADC vbat: avg=55642 ...
  Vbat: 4234 mV at divider input (2801.84 mV raw * 1.511)
  Battery raw: 55642                       ← adc_battery_voltage = 55642
```

## 7. Запись измерений в память (отдельно от запросов)

Измерительный поток (активный проект) сохраняет сэмплы по 3 байта:

```
[pressure_hi] [pressure_lo] [temperature]
```

- давление — 16 бит big-endian (тот же `adc_pressure` raw, unsigned);
- температура — `int8_t`, **знаковый**, диапазон ±127 °C, 1:1 °C/LSB
  (целая часть, округление до ближайшего). НЕ путать с живой телеметрией
  (там 0.005 °C/LSB, поле 5) — это отдельный, более грубый формат ради
  экономии места во флеш-памяти (ТЗ: 0…105 °C с точностью 1°).
  Байт читается на клиенте как знаковый (`int8_t`/`.toSigned(8)` в Dart),
  а не как `0…255`.
  При ошибке чтения датчика в этом цикле измерения прошивка пишет `0`
  (а не NaN/неопределённое значение — было UB до фикса от 2026-09-22).
  Формат чтения через memory-команды — `MemoryReadResponse`, поле 15
  (см. «Память» в предыдущих заметках по интеграции).
